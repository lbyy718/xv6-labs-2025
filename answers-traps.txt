1. RISC-V passes the first eight integer or pointer arguments in a0-a7.
   For the call to printf in main, a0 contains the address of the format
   string, a1 contains 12, and a2 contains 13.  Thus a2 holds 13.

2. There is no call to f or g in main.  The compiler inlined and then
   constant-folded f(8) + 1 to 12.  Likewise, there is no call to g in f;
   f contains the addiw instruction that implements x + 3 directly.

3. printf starts at address 0x6f6 in user/call.asm.

4. The call instruction is at 0x30, so ra contains 0x34 immediately after
   the jump to printf.  RISC-V stores the address of the instruction following
   the call in ra.

5. The output is:

     He110 World

   57616 is 0xe110.  On little-endian RISC-V, i = 0x00646c72 is stored as
   the byte sequence 72 6c 64 00, which is the string "rld".  On a big-endian
   machine, i would need to be 0x726c6400 to produce the same byte sequence
   and output.  57616 would not need to change: %x formats its numeric value,
   so its in-memory byte order does not affect the printed digits.

6. The value printed for y is indeterminate (the program has undefined
   behavior).  The format string requests a second integer argument, but the
   caller supplies only one.  printf therefore reads whatever value happens
   to be in the next argument slot/register; no particular numeric value is
   guaranteed.
